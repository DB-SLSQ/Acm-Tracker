## ACM 训练台 v1.0.18

这一版三件事：新增**区域赛备赛计划**（给个比赛日期，AI 排一条到赛前的训练路线）、修掉**推题模型训练起不来**的 bug，
以及让**提交记录每天自动补一次**（题单勾选仍然只由你自己点）。

### 下载

**Windows**：下载下方的 `ACM Trainer Setup 1.0.18.exe`，双击安装。装过旧版的直接覆盖，本地数据不会丢。
Windows 提示「已保护你的电脑」就点「更多信息」→「仍要运行」，个人项目没买数字签名，是正常情况。

**Linux（Ubuntu / Debian 等）**：

- `.AppImage`：下载后 `chmod +x ACM.Trainer-1.0.18.AppImage`，直接双击/命令行运行；
- `.deb`：`sudo dpkg -i ACM.Trainer-1.0.18.deb` 安装，装完在应用菜单里找 ACM Trainer。

### 新增：区域赛备赛计划

在「备赛计划」面板里填上要打的区域赛（可以填多场，每场带日期），点一下让 AI 排计划，它会结合你的
CF 分数、已做题目分布、弱项标签和最近训练量，给出一条**从今天排到比赛前一天**的路线：

- 分段推进（弱项补强 → 综合模拟 → 赛前调状态），每段写清练什么、多少题；
- 每周多少题、哪天休息，按你的实际水平来，不是一刀切；
- 团队里其他人也会被算进去，需要合练的地方单独标出来；
- 顶部有倒计时和总题量，短阶段（不到 7 天）会直接显示「N 天 · 共 X 题」。

嫌计划太狠或太松，可以选目标档位（稳铜 / 冲银 / 冲金）重排一次——铜牌按 1400-1700 分段的强度排，
冲银 1500-1900，冲金 1900-2200。想冲银就别用铜牌的题量糊弄自己。

### 修复：推题模型训练一点就报 `spawn ... ENOENT`

现象是在设置里填好场次点「开始训练」，日志立刻跳出：

```
训练没能启动：spawn C:\...\ACM Trainer.exe ENOENT
```

三个原因叠在一起，全是**只有打包成 exe 才会犯**的错（`npm start` 跑源码永远正常，所以我之前没抓到）：

1. 启动训练子进程时把工作目录设成了 `app.asar`——那是 Electron 的虚拟路径，系统根本 chdir 不进去，
   于是 `spawn` 直接 ENOENT，程序本体其实好端端躺在那儿；
2. `process.execPath` 打包后是 `ACM Trainer.exe` 而不是 `node.exe`，没加 `ELECTRON_RUN_AS_NODE`
   的话它会把训练脚本当成「要打开的文件」再弹一个窗口；
3. 子进程启动失败时「训练中」状态不复位，界面会一直卡在训练中。

现在工作目录换成真实的 `resources\`，子进程显式走 node 模式，失败也会立刻把状态和原因写回面板。
另外如果应用被移动过、本体路径失效，会直接提示「请重启应用」，而不是甩一句看不懂的 ENOENT。

训练本身没动：还是从已结束的 rated 比赛里学「以你现在的水平能不能做出这道题」，300 场大约十几分钟，
期间可以关掉设置面板，跑完会在后台把模型存进本地库。

### 改进：提交记录每天自动补一次

题单里的**勾选永远只由你自己点**——做完了勾一下，勾错了取消，应用不会替你判断。

但「你做过哪些题」这份底账得是新的，不然排计划时会把早就做过的题又推给你。所以加了：
**每天打开应用时，自动补一次上次同步之后的提交**（只抓新增的那部分，对 Codeforces 就是一个请求）。

- 一天最多真跑一次，时间记在本地库，「连续开关几次应用」不会反复去敲 Codeforces；
- 网络不好就静默跳过，不弹错误、也不拖慢首屏；
- 补到了新记录只会影响「排除做过的题」和统计数字，**不会动你的勾**。

顺手修了一个计数错误：以前统计「这次同步到几条新提交」永远等于抓回来的总条数，
因为 `INSERT OR IGNORE` 跳过已存在的行时也被算成了新增。现在按实际写入行数统计。
