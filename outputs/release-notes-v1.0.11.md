## ACM 训练台 v1.0.11

修一个「看着像玄学」的问题：**CF 一上分，每日训练的题单就跟着重排了。**

### 下载

下载下方的 `ACM Trainer Setup 1.0.11.exe`，双击安装。装过旧版的直接覆盖，本地数据不会丢。
Windows 提示「已保护你的电脑」就点「更多信息」→「仍要运行」，个人项目没买数字签名，是正常情况。

### 问题是什么

有人反馈：上分之后重新抓了一次账号数据，每日训练的题单整个变了样。按常理，他并没有点「重新生成计划」，
计划不该动——界面也确实写着「做过的题会留在原位、自动打勾，**不会被换成别的题**」。

题号确实一个没换。真正变的是**题量**（以及由它带出来的周数、每天做几道），而且还有一批题的**前后顺序**
变了。两件事叠在一起，看过去就是「题单被重排了」。

### 两个原因

**一、题量没被计划钉住，是拿当前的分数现算的。**

计划确实存在库里、题号也钉住了，但「一共做多少题」这一步走的是另一条路：拿目标分减去**当前**分数，
每 100 分算 60 题。于是 CF 一上分，差距变小、题量直接缩水，周数跟着少，整条日程往前挤。
掉分则反过来，排得更多。举个数：目标 2150，从 1751 分上到 1811 分，题量从 239 掉到 203。

**二、按难度排序的比较器不是「全序」，同分的题顺序会漂。**

计划最后要按难度排一遍、再「分层发牌」摊到每一天。比较器只比难度、不管同分怎么办，
那么同分的那批就保留「原来是什么顺序」——而「第一次生成」和「沿用旧计划」两条路径给出的
原始顺序并不一样。结果就是题号集合一模一样，每天做哪几道却整体挪了位。

### 改了什么

- 每份计划现在会**连「生成它时的分数」一起存下来**。沿用旧计划时，题量、阶段数、周数、
  每档目标分全按当时那个分数算，不再看实时分数。
- **分数怎么变都不会动你手上的计划。** 想让计划跟着现在的分数重排，点右上角「重新生成计划」。
- 排序比较器补上「同分时按题号定序」，题单的顺序从此稳定。
- 界面顺带说清楚了：分数和计划不一致的时候，摘要会显示成
  「**计划定下时 1751 分 → 2100 分**……**你现在的分数是 1811 分（+60）**」，
  并提示想按新分数重排就点「重新生成计划」，不再笼统地写成「当前 X 分」。

已经在手的计划**不用做任何处理**：第一次打开这一版时会按当前分数把它钉住，升级本身不会改动你的计划。

### 验证

- `.dev/verify-plan-pin.mjs` **37 项全过**：上分 60 / 掉分 120 都不动题量、周数、阶段、区间、
  题号和顺序；触发重排时才按新分数重算；老计划的补写路径也走了一遍。
  另外做了**两次反向验证**——分别把「钉分数」和「同分定序」两块撤掉重跑，
  确认测试真的会红（撤掉第一块时题量从 239 漂到 203，正是反馈里的现象）。
- 项目自带的计划自检 14 项全过，含「73 个做题日，每天从易到难」。
- 在真 Electron 窗口里截了两种状态（分数没变 / 上分之后），确认摘要文案和题单都没问题。

### 说明

计划里所有「会自己变」的东西，依据都在快照里；只有设置变了、或者你点了「重新生成计划」才会重挑。
这条已经写进项目的开发规约，以后不会再有「悄悄重排」了。
